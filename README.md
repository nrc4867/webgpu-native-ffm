# webgpu-native-ffm

Java bindings for [wgpu-native](https://github.com/gfx-rs/wgpu-native) over the Foreign Function & Memory API
(JDK 25), with the native library in a separate jar per platform.

| Release | Bundles wgpu-native |
| --- | --- |
| 0.1.0 | v29.0.1.1 |

## Use it

Packages are published to GitHub Packages, which needs a login even for public packages. Locally, put a classic
personal access token with the `read:packages` scope in `~/.gradle/gradle.properties`:

```properties
GitHubPackagesUsername=<your GitHub user>
GitHubPackagesPassword=<token>
```

In GitHub Actions, the workflow's own `GITHUB_TOKEN` with `packages: read` is enough.

```kotlin
repositories {
    maven {
        name = "GitHubPackages"
        url = uri("https://maven.pkg.github.com/nrc4867/webgpu-native-ffm")
        credentials(PasswordCredentials::class)
    }
}

dependencies {
    implementation("dev.chieppa:webgpu-native-ffm:0.1.0")
    // One natives jar per platform the app runs on.
    runtimeOnly("dev.chieppa:webgpu-native-ffm:0.1.0:natives-windows-x64")
}
```

The natives classifiers are `natives-windows-x64`, `natives-linux-x64`, `natives-linux-arm64`, `natives-macos-x64`
and `natives-macos-arm64`.

Load the library before the first call into the bindings, and run with `--enable-native-access=ALL-UNNAMED`:

```java
WgpuNative.load();
int version = wgpu_h.wgpuGetVersion();
```

`WgpuNative.load()` copies the library into the user's cache (a folder named after its content hash) and loads it
from there.

## Build

`./gradlew check` runs the tests against this machine's natives jar. `./gradlew nativesJars` packs all five.

The bindings in `src/main/java/dev/chieppa/webgpu/ffi` are generated by
[jextract](https://jdk.java.net/jextract/) and checked in. To regenerate them after changing the wgpu-native
version (`gradle/libs.versions.toml` and the checksums in `buildSrc/.../WgpuArchives.kt`) or the symbols in
`bindings.includes`:

```
./gradlew generateBindings -Pjextract.home=<jextract folder>
```

## Release

Push a tag `v<version>`, such as `v0.1.0`. The Publish workflow runs the checks, publishes every jar to GitHub
Packages at that version and creates a GitHub release with the jars attached.
